# panco NC cross-validation oracle

This directory pins **independent network-calculus reference bounds** for
spar-network's NC engine, computed by [panco][panco] — Anne Bouillard's own
reference implementation of the LP-based deterministic-network-calculus
results spar's `tfa.rs` (FP-TFA/TFA++) and the planned `plp.rs`
(REQ-NC-PLP-001) are derived from.

The Rust test `crates/spar-network/tests/nc_validation.rs` rebuilds each
fixture below in spar's own `TfaFlow`/`ServiceCurve` types, runs
`tfa_bound`, and asserts the two things a hand-computed golden fixture
**cannot** check on its own:

1. **Soundness** — `spar_bound ≥ panco_exact`. panco's *exact* bound
   (`FifoLP(polynomial=False)`, the Bouillard–Stea ELP, ValueTools 2012)
   is the true worst-case delay of a FIFO tandem: no sound NC method can
   return a value below it. If spar's TFA bound ever dips under the exact
   bound, spar is provably **unsound** — and this is the *only* check that
   can catch that, because an unsound (optimistic) bound is also `≤ TFA`.
2. **Arithmetic agreement** — `spar_bound ≈ panco_TFA` (within rounding).
   panco's `TfaLP` is an independent LP-based TFA. Agreement to integer
   rounding confirms spar implements the *TFA method* correctly, not merely
   *some* sound bound (a sound-but-10×-pessimistic bug passes soundness but
   fails agreement).

This is oracle-kind-(b) (NC-tool agreement) from the v0.18 corpus plan —
the cheap, deterministic validator. The stronger simulation floor
(OMNeT++/INET, oracle-kind-(a)) is deferred to REQ-NC-SIM-FLOOR-001, and
note the **service-model-match constraint**: panco/xTFA/DNC validate
FIFO/CBS/ATS bounds, *not* 802.1Qbv TAS gates — a TAS schedule must be
validated against a TAS-matched simulator, not against these NC tools.

## Unit mapping (spar ↔ panco)

spar works in **bytes + picoseconds + bits/s**; panco is unit-agnostic.
The generator models everything in **bits + seconds** and the Rust test
converts panco's microseconds to picoseconds (`µs × 1e6 = ps`):

| quantity | spar | panco (this generator) |
|---|---|---|
| burst | 1500 bytes | `1500 × 8` bits |
| sustained rate | 100 Mbps = `1e8` bits/s | `1e8` |
| service rate | 1 Gbps = `1e9` bits/s | `1e9` |
| latency | 10 µs = `10_000_000` ps | `10e-6` s |

Per-link max-service (shaping) is set non-binding (`TokenBucket(0, 1e12)`)
so panco's TFA matches spar's pure rate-latency TFA (spar's `tfa_bound`
models no output shaping).


## Pinned reference bounds (microseconds)

Generated by `panco_bench.py`. `flows` are listed in the order
`all_delays` returns them.

### fixture 1 — `tandem_cross`
2-server tandem; tagged flow `[0→1]`, cross flow `[0]`. Both
`α = (1500 B, 100 Mbps)`; servers `β = (1 Gbps, 10 µs)` and `(1 Gbps, 5 µs)`.

| flow | TFA | SFA | PLP | **EXACT** |
|---|---|---|---|---|
| tagged `[0,1]` | 54.3861 | 40.3333 | 39.0 | **39.0** |
| cross `[0]` | 34.0 | 35.3333 | 34.0 | **34.0** |

### fixture 2 — `single_flow_tandem`
Same servers; one flow `[0→1]`.

| flow | TFA | SFA | PLP | **EXACT** |
|---|---|---|---|---|
| `[0,1]` | 41.1872 | 27.0 | 27.0 | **27.0** |

### fixture 3 — `three_server_line`
3 servers `β = (1 Gbps, 10 µs)` each; tagged `[0→1→2]`, cross1 `[0→1]`,
cross2 `[1→2]`; all `α = (1500 B, 100 Mbps)`.

| flow | TFA | SFA | PLP | **EXACT** |
|---|---|---|---|---|
| tagged `[0,1,2]` | 134.7037 | 99.04 | 68.4 | **68.4** |
| cross1 `[0,1]` | 86.7784 | 73.2 | 58.4 | **58.4** |
| cross2 `[1,2]` | 100.7037 | 81.22 | 57.98 | **57.98** |

The **PLP** column is the target for REQ-NC-PLP-001: spar's `plp_bound`
must land on these values (PLP = EXACT on these small feed-forward trees),
inside the sandwich `EXACT ≤ plp ≤ TFA`.
