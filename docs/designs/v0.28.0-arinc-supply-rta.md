## Problem

Threads bound *inside* an ARINC-653 partition (gale/gust's tickless
cooperative inner executor) do not run against wall-clock — they run
against the partition's **supply**. A periodic resource `Γ = (Π, Θ)`
(period `Π`, budget `Θ`, already parsed for the `ARINC-WINDOW-UTILIZATION`
gate) delivers, in the worst case, *no* CPU for a contiguous **blackout**
of `2(Π−Θ)` before the budget following it — note this is *twice* the
naive `Π−Θ` window gap. spar had no supply model, no blackout derivation,
no demand-vs-supply test, and no non-preemptive blocking term
(`rta.rs` kept the explicit no-blocking assumption). This closes that gap
by *reusing the verified jittered+blocking recurrence unchanged*.

## Approach — two paths

**(b) Supply-derived release jitter (jitter-encoded path).** Inject
`J_i = 2(Π−Θ)` as every inner task's release jitter and emit the
busy-window `w`-form

```text
w_i = fixed point of  w = C_i + B_i + Σ_{hp j} ⌈(w + J_j)/T_j⌉·C_j
R_i = 2(Π−Θ) + w_i
```

sound under the side condition `w_i ≤ Θ` (the busy window fits inside the
single contiguous budget after the worst-case blackout). Both `w_i` and
the side-condition test come from **one** call:
`compute_response_time_jittered_blocking(C_i, deadline=Θ, jitter=0, B_i,
hp=[(T_j,C_j,2(Π−Θ))], isr)` returns `Converged(w) ⟺ w ≤ Θ` and
`Diverged ⟺ w > Θ` — the divergence bound *is* the side condition. The
supply-derived jitter is pulled out of the own-jitter slot and added back
as `2(Π−Θ)`; it appears inside each higher-priority ceiling as `J_j`.

**(c) Cooperative non-preemptive blocking.** Run-to-completion polls let
one already-dispatched lower-priority segment block a release:
`B_i = max_{j ∈ lp(i)} C_j^seg`. Derived automatically as the max
lower-priority task WCET (run-to-completion default `C_j^seg = C_j`); a
task that yields across polls overrides its segment via
`Timing_Properties::Poll_Segment_Time`. Carried in the recurrence's
existing `blocking` slot — a pure additive constant.

**(d) Demand-vs-supply fallback.** When `w_i > Θ` the jitter encoding is
no longer guaranteed sound; fall through to

```text
lsbf_Γ(t) = ⌊Θ·(t − 2(Π−Θ))/Π⌋   for t > 2(Π−Θ),  else 0
rbf_i(t)  = C_i + B_i + Σ_{hp j} ⌈(t + J_j^extra)/T_j⌉·C_j
R_i       = min { t ∈ (0, D_i] : rbf_i(t) ≤ lsbf_Γ(t) }
```

No supply-derived jitter appears in `rbf` — the `sbf` already carries the
blackout; reusing it would double-count. The minimiser is found by a
monotone fixed point (`t_next = 2(Π−Θ) + ⌈demand·Π/Θ⌉`, re-evaluate,
iterate) rather than a linear scan, so it is efficient on picosecond-scale
inputs. **Unschedulable / ill-formed sets (no admissible `t`, `Θ > Π`,
`Π=0`, `Θ=0`) produce a hard `Error`** of the same class as the
`ARINC-WINDOW-UTILIZATION` overcommit gate — never a silently-wrong
number. The v1 fallback is scoped to `J^extra = 0`; the extra-jitter +
fallback combination is **declined** with the same hard Error rather than
analyzed with jitter dropped (which would make the demand an
under-estimate → unsound).

## Discovery & the no-double-analysis invariant

Inner threads are discovered by **virtual-processor tree containment** (a
`VirtualProcessor` ancestor) and must carry **no**
`Actual_Processor_Binding`. Such threads are `__unbound__` to the ordinary
`RtaAnalysis` (which requires a processor binding and skips the unbound),
so the supply pass is their **sole** analyzer — no contradictory
wall-clock number (which would ignore the 1400 µs blackout) is emitted for
the same thread. The `integration_no_double_analysis_from_rta` test pins
this reconciliation.

## Worked example (golden test)

`Γ = (Π = 1000 µs, Θ = 300 µs)`, blackout `2(Π−Θ) = 1400 µs`. Three inner
tasks (`D_i = T_i`, priority 1 highest), derived `B = 100/100/0` µs:

| task | C (µs) | T=D (µs) | w (µs) | R = 1400 + w (µs) |
|---|---|---|---|---|
| τ1 | 20 | 5 000 | 120 | **1 520** |
| τ2 | 50 | 10 000 | 170 | **1 570** |
| τ3 | 100 | 20 000 | 170 | **1 570** |

**Form note (pinned in the assertion):** these are the **busy-window
w-form** (`R = 2(Π−Θ) + w`). They coincide with the engine R-form on this
task set but differ in general (the R-form is the more pessimistic, sound
one). A future mismatch must not be "fixed" by silently switching forms.
The linear `lsbf` fallback is visibly more conservative on the same set
(e.g. τ3 → ≈1967 µs vs 1570 µs) — a deliberate regression pair.

## What is proven vs assumed (the #294 lesson)

**PROVEN** (Lean, 0 `sorry`, `ArincSupply.lean`):

- The constant blocking term folds into the release jitter
  (`rtaStepJitteredBlocking_fold`), so monotonicity
  (`rtaStepJitteredBlocking_mono`) and least-fixed-point convergence in
  `deadline+1` steps (`rtaBlocking_finds_least_fixed_point`) transfer from
  the existing `RTAJittered.lean` theorems by the same
  `bounded_mono_nat_seq` argument. This lifts, for the cooperative case,
  the no-blocking assumption `rta.rs` documented.
- `lsbf_Γ` is monotone in `t` (`lsbf_mono`) and zero below the blackout.
- **Conditional fallback soundness** (`fallback_sound_of_supply_guarantee`):
  *given* the supply guarantee, passing `rbf(t) ≤ lsbf_Γ(t)` implies real
  demand never exceeds real supply at `t`.

**ASSUMED** (the OS's obligation, the theorem's hypothesis — *not* spar's
proof): that the partition scheduler actually delivers supply ≥ `lsbf_Γ(t)`
in every interval of length `t`. gust owns this contract
(`SupplyGuarantee` is a Lean hypothesis, not a proven lemma).

## Honesty caveats (carried per issue #331)

- **Sound-WCET inputs only.** The emitted bound is only as sound as its
  inputs: `C_i`, `C_j^seg`, and the `Θ` sizing must come from a **sound
  static WCET bound**, not measured high-water-marks (DWT-style cycle
  counters are observations, not bounds). gale is pairing this with a
  synth-emitted static cycle bound (pulseengine/synth#778) so the whole
  chain is measurement-free.
- **No tool-qualification credit.** An unqualified proof assistant carries
  no tool-qualification credit by itself; the machine-checked bound is
  rigor and a safety-case input feeding a tool-confidence argument, not a
  certification claim.

## Falsification statement (v0.28.0)

Reverting the supply-derived jitter (`J_i = 2(Π−Θ)` → `0`) drops the
golden bounds from 1520/1570/1570 µs to 120/170/170 µs — the wall-clock
numbers that ignore the partition blackout; the `golden_jitter_path_*`
assertions fail. Reverting the `w_i > Θ` dispatch to always take the
jitter path makes `fixture2` emit an unsound jitter-encoded number instead
of the conservative fallback 2567 µs. Removing the ill-formed guard makes
`fixture3` / `integration_ill_formed_partition_errors` emit a bound for an
unschedulable set instead of the hard Error.
